# DexSearch: notes for coding agents

Offline Pokédex and team builder for Android. Kotlin on the plain `android.view` / `android.widget` framework:
no Gradle, no AndroidX, no XML layouts, no third-party libraries. Package `demo.dex`, all code in `src/demo/dex/*.kt`,
one Activity per screen. README.md covers what the app does and how releases reach phones.

## Build and check

```
./build.sh                                        # aapt2, kotlinc, self-check, R8, zipalign, apksigner
adb install -r -i demo.dex dexsearch.apk          # -i demo.dex: the app is its own installer, so its updates skip the confirm
adb shell am start -n demo.dex/.MainActivity
```

- Needs Android SDK platform `android-36` and build-tools `36.0.0` (under `$ANDROID_HOME`, default `~/Android/Sdk`),
  JDK 17+, Kotlin 2.x (`kotlinc` on `PATH` or `KOTLINC=`).
- The build runs `java demo.dex.Dex assets` (`Dex.main`) before packaging: data checks plus the translation check
  below. A failed `check(...)` stops the build. Run `./build.sh` after every change; it is the only test suite.
- versionCode is `git rev-list --count HEAD`. `debug.keystore` is gitignored and must be kept: updates signed with
  another key do not install over the existing app.
- R8 prints "malformed kotlin.Metadata" lines for Kotlin newer than 2.2. They are noise (no Kotlin reflection).

## Translations

- UI text goes through `L.t("English")`, `L.f("English %d", n)` or `L.k("English")` (a key translated later).
  The English text is the key.
- `assets/lang/{pl,es,ja}.tsv`: one `English<TAB>translation` per line, `\n` for a line break.
- `Dex.main` scans `src/demo/dex/*.kt` with a regex for string literals in those calls. Each table must hold exactly
  that key set: a missing key and an unused key both fail the build. Format conversions must match between key and
  value (`%d`, `%s`, positional `%1$d` allowed in the value).
- So: always pass a literal. `L.t(variable)` is invisible to the check. When a string changes, change its key in all
  three tables and delete the old row.

## Data and assets

- `assets/` is generated by `gen_data.py` (it runs the other `gen_*.py` scripts) and committed. Do not hand-edit
  the TSVs; change the generator and rerun it. File formats are documented at the top of `gen_data.py` and on the
  matching classes in `Dex.kt`.
- `pdb_cache/`, `evidence/` and `build/` are local and gitignored.

## UI conventions

- Build views with the helpers in `Ui.kt`: `Ui.panel`, `Ui.wide`, `Ui.margins`, `Ui.chip` / `Ui.chipBar` /
  `Ui.addChip`, `Ui.row` + `Ui.bind`, `Ui.pill` / `Ui.typePills`, `Ui.hero`, `Ui.text` / `Ui.muted` / `Ui.caption`.
  Colors come from `Ui` (`SURFACE`, `FILL`, `TEXT`, `MUTED`, `ACCENT`, `UP`, `DOWN`, `Ui.color(type)`,
  `Ui.tonal`, `Ui.ink`); they follow day and night mode.
- Type labels follow the user's Settings choice (text, icon, glyph, pixel). Do not force a style.
- Sizes in dp via `Ui.dp`; text sizes in sp. Layouts must work at 360 dp wide.
- `LinearLayout` weight gotcha: a bare `View` spacer with weight claims the whole height when its parent is
  measured `AT_MOST` (inside a `ScrollView`), and squeezes its siblings to nothing. Give the weight to a real
  `TextView` with gravity instead.
- Comments say why, not what. Match the surrounding code. Caches and lists are bounded; the comment on each one
  states its limit and memory cost.

## Testing on a phone

- Take a screenshot after every tap (`adb exec-out screencap -p`). A blind tap can land in a search field and type.
- `adb shell input tap` is often swallowed by horizontally scrolling chip bars; a 90 ms swipe on one point works.
- `adb shell input text` stops at the first space.
- The phone holds the owner's real teams. Never edit or delete them, never uninstall the app, never clear its data.

## Releases and git

- `./publish.sh` builds the committed state, pushes and creates GitHub release `v<versionCode>`, which deploys the
  APK and `version` to GitHub Pages. Pushing, releasing and changing repository settings need the owner's explicit
  go-ahead each time.
- Commit messages: one plain sentence describing what the user can now do. No AI attribution of any kind: no
  `Co-Authored-By` trailer for an assistant, no "Generated with" line, in commits, PRs, comments or files.
